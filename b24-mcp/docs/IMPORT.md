# Порядок dry-run импорта исходной базы

## Правила

- Исходный файл `data/raw/ЕДИНАЯ_БАЗА_КОНТАКТОВ_CRM_2026.xlsx` **не изменяется**:
  он только читается, все результаты пишутся в `data/import/`.
- Скрипт импорта не обращается к Битрикс24 вообще: ни чтения, ни записи.
- Загрузка в CRM выполняется отдельно и только после явного подтверждения.

## Запуск

```bash
npm run import:dry-run
# или с явными путями
npx tsx src/import/run-import.ts data/raw/<файл>.xlsx data/import
```

## Что получается

| Файл | Содержимое |
|---|---|
| `companies_import.xlsx` | Уникальные компании: название, телефон, email, правовая форма, качество |
| `contacts_import.xlsx` | Контактные лица с привязкой к компании |
| `leads_review.xlsx` | Строки, где непонятно, компания это или человек, либо компания не определилась |
| `duplicates.xlsx` | Группы совпадений по телефону, email и нормализованному названию |
| `invalid_rows.xlsx` | Строки без телефона и без email |
| `data_quality_report.md` | Сводный отчёт качества |

## Как читаются данные

- Телефон приводится к E.164; ключ сравнения — последние 10 цифр.
- Ячейки «Компания» и «Имя контакта» обе могут содержать название организации;
  выигрывает вариант с правовой формой (`ООО "Линер"` вместо `"Линер"`).
- База — B2B, поэтому по умолчанию значение считается **названием компании**.
  Человек распознаётся только по сильному признаку: отчество или инициалы.
  Два простых кириллических слова («Арт Багет») остаются компанией, но
  помечаются `company_vs_person_ambiguous` и попадают в `leads_review.xlsx`.
- Адреса вида `79155238324@yandex.ru` помечаются синтетическими и исключаются
  из группировки по email, чтобы не склеивать разные организации.

## Решения, которые нужно принять до загрузки

1. Правило слияния дублей (побеждает самая полная или самая свежая строка).
2. Судьба 519 строк из `leads_review.xlsx`: лиды, компании или отбраковка.
3. Попадают ли синтетические email в карточку (риск: они уйдут в рассылки).
4. Ответственный по умолчанию для импортируемых карточек.
5. Созданы ли пользовательские поля Canvas Lab (см. `BITRIX24_CHECKLIST.md`).

## Порядок боевой загрузки (после подтверждения)

1. Тестовый портал, `WRITE_ENABLED=true`, партия 20–50 карточек.
2. Сверка `crm_find_duplicates` с реальным содержимым портала — внутрифайловых
   проверок недостаточно.
3. Ручная проверка выборки карточек.
4. Полная загрузка партиями с паузами (лимит 2 rps).
5. Только затем — боевой портал.
