## Ключевые решения

**Единственный адаптер.** HTTP выполняется только в `bitrix/client.ts`.
Имя REST-метода никогда не приходит из аргументов инструмента: его выбирает
код репозитория, а `assertAllowed` сверяет с allowlist. Методы удаления
отсутствуют в списке — не «запрещены проверкой», а физически не описаны.

**Универсальный API вместо устаревших списков.** Документация Битрикс24
помечает `crm.company.list` и `crm.deal.list` как DEPRECATED и рекомендует
`crm.item.list` (`entityTypeId`: 2 — сделка, 3 — контакт, 4 — компания).
Шлюз использует `crm.item.*`; старые методы оставлены в allowlist как
запасной путь на случай нестандартных портальных настроек.

**Поиск по телефону/email — через индекс дублей.** `crm.duplicate.findbycomm`
находит записи независимо от того, как номер записан в карточке (максимум
20 значений за вызов). Фильтр `%PHONE` этого не гарантирует.

**Задачи — два взаимозаменяемых диалекта.** `tasks.task.list` в Битрикс24
отвечает либо классическим контрактом вебхука (объектный фильтр, `start`), либо
REST v3 (`/rest/api/…`, массив условий, `pagination`, `result.items`). Оба
реализованы в `bitrix/tasks.ts` за общим интерфейсом `TasksApi`; клиент умеет
ходить на v3-endpoint через `call(..., { api: 'v3' })`. Выбор — через
`TASKS_API_MODE` (по умолчанию `legacy`), подтверждается `npm run validate:live`.
Доменная логика диалекта не видит: она работает с нормализованным `Task`.

**Доменная модель не знает про UF_CRM_*.** Поля Canvas Lab (`segment`,
`estimated_monthly_volume`, `next_step`, `loss_reason`, …) объявлены как
доменные имена. Реальные коды приходят из `FIELD_MAP_COMPANY` /
`FIELD_MAP_DEAL`. Незамапленное поле не пишется и не читается, а инструмент
явно сообщает, что его пропустили. Идентификаторы полей нигде не выдуманы.

**Ошибки портала → доменные ошибки.** `mapBitrixError` переводит коды
Битрикс24 в `AUTH / FORBIDDEN / NOT_FOUND / RATE_LIMITED /
UPSTREAM_UNAVAILABLE / INVALID_REQUEST`, не пробрасывая исходный текст —
в нём может оказаться URL вебхука.

**Повторы только для чтения.** Retry с экспоненциальной паузой применяется
исключительно к методам из read-списка и только при retryable-ошибках
(`QUERY_LIMIT_EXCEEDED`, `OVERLOAD_LIMIT`, 5xx, таймаут). Любая запись
выполняется один раз; при исчерпании попыток операция уходит в
dead-letter queue.

**Идемпотентность.** Ключ операции скоупится именем инструмента и
отпечатком аргументов. Тот же ключ с другими аргументами — ошибка, а не
тихий повтор. Плюс `ReplayGuard` в памяти процесса как быстрый барьер.

**Закрепление клиента.** `agent_assignments` — единственный источник
правды о владельце. Захват выполняется под эксклюзивной файловой
блокировкой (read-modify-write + атомарный `rename`), поэтому гонка двух
агентов заканчивается ровно одним победителем. Блокировка живёт
`ASSIGNMENT_LOCK_MINUTES` и после истечения освобождает объект.

## Риски и ограничения

| Риск | Статус | Что делать |
|---|---|---|
| Состояние (assignments, метрики, идемпотентность) хранится в файлах | Принято для одного инстанса | При горизонтальном масштабировании — Postgres (`SELECT … FOR UPDATE`) или Redis |
| `tasks.task.list` существует в двух диалектах (классический webhook и REST v3) | Оба реализованы в `bitrix/tasks.ts`, переключение через `TASKS_API_MODE`; какой отвечает на портале — определяет `npm run validate:live` | Выставить `TASKS_API_MODE` в `confirmed_mode` из отчёта проверки |
| Стадии `WON/LOSE/APOLOGY` определяются по префиксу | Работает для стандартных воронок | Для кастомных статусов свериться с `crm.status.list` |
| `crm.item.list` ограничен 50 записями на страницу | Учтено пагинацией и лимитом 500 записей на аналитический запрос | Для полной выгрузки — отдельный batch-процесс |
| Транзитивные уязвимости: `uuid@8` (через exceljs), `@hono/node-server` (через MCP SDK) | Moderate, не эксплуатируются: buf не передаётся, serve-static не используется, Windows не целевая ОС | Обновить, когда выйдут исправленные версии зависимостей |
| Дубли ищутся только внутри Excel-файла | Ожидаемо на этапе dry-run | Сверка с порталом — после подключения тестового вебхука |
| Разделение «компания/контакт» в исходной базе эвристическое | 519 строк вынесены в `leads_review.xlsx` | Ручная проверка перед импортом |
